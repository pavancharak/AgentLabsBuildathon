## Gateway hardening: mutate, verify, watch it fail (35-46)

The same pattern each time: generate something valid, mutate exactly one thing, re-verify,
confirm rejection. See [Detect tampering](/guides/detect-tampering) for three of these run
live with real output.

| # | Name | What's mutated |
|---|---|---|
| 35 | Replay Attack | The same authorization submitted twice |
| 36 | Parameter Tampering | A parameter inside the executable content |
| 37 | Action Substitution | The `action` field |
| 38 | Target Substitution | The `target` field |
| 39 | Policy Substitution | The referenced policy |
| 40 | Signature Forgery | The signature itself, signed by a different key |
| 41 | Expired Authorization | The clock, past `expiresAt` |
| 42 | Nonce Reuse | The nonce, submitted a second time |
| 43 | Stolen Authorization | A valid envelope replayed by a different party |
| 44 | Direct API Bypass | Attempting to skip the gateway entirely |
| 45 | Connector Bypass | Attempting to reach a connector without a valid session |
| 46 | TOCTOU Protection | The full check-vs-use gap, end to end |

## Not yet indexed above (96-105)

<Info>
This page's own header claims "All 94 numbered examples" and its tables stop at 95 — both
already stale before this note, since tutorials 96 through 104 exist, run in
`scripts/run-examples.ts`'s unattended list, and pass, but were never added to this page.
Not backfilled here (out of scope for the change that added the note below); flagged rather
than left silent.
</Info>

**105 — Tenant Key Isolation.** Demonstrates the per-tenant signing-key fix
(`docs/VERIFICATION-GAPS.md` G-32): a transaction with a provisioned `tenant.<tenantId>`
key signs and verifies only under that key, an unprovisioned tenantId falls back silently to
the shared default key, and a transaction with no tenantId is unaffected. Newly added to
`scripts/run-examples.ts`'s list (`docs/VERIFICATION-GAPS.md` G-37) — it existed and worked
standalone since its own commit, but `npm run examples` never exercised it until now.

**106 — API Key Issuance (Writing a New Policy).** A brand-new `policies/api-key-issuance/1.0.0`
policy and worked example showing how to author a policy correctly under the fail-closed
`boundSignals` discipline (G-33) and zero-conflict shape (G-39) from the start, rather than
retrofitting it afterward the way all 10 pre-existing policies needed. Also in
`scripts/run-examples.ts`'s list from its first commit.
